# Registros de decisiones de arquitectura · Sesión 15

Las cinco decisiones siguientes corresponden a los temas solicitados para el
proyecto final y describen la arquitectura que está implementada actualmente.

| ADR | Decisión | Estado |
| --- | --- | --- |
| [ADR-001](ADR-001-alcance-del-dominio.md) | Dominio y alcance de SisGanado | Aceptada |
| [ADR-002](ADR-002-persistencia-por-subdominio.md) | Persistencia SQL y documental por subdominio | Aceptada |
| [ADR-003](ADR-003-patrones-de-diseno.md) | Patrones de diseño aplicados al flujo sanitario | Aceptada |
| [ADR-004](ADR-004-autenticacion-y-autorizacion.md) | Autenticación y autorización de la API | Aceptada |
| [ADR-005](ADR-005-plataforma-y-despliegue.md) | Plataforma y estrategia de despliegue | Aceptada |

Cada ADR registra contexto, decisión, alternativas y consecuencias, incluido
al menos un costo o una limitación. Para el diagrama C4, el modelo de datos,
seguridad y lecciones, consulte [Arquitectura de la defensa](../arquitectura-sesion15.md).

## Mantenimiento

- Documentar una decisión por ADR.
- Mantener las alternativas y limitaciones explícitas.
- Si una decisión cambia, registrar el cambio y enlazar el ADR que la reemplaza.
